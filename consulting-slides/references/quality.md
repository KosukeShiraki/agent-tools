# 最終品質チェック

納品前に、全ページについて次を確認する。1つでも×があれば直してから出す。

## 削除テスト（ページ単位・最初にやる）

図解は「足すものがなくなったとき」ではなく「削れるものがなくなったとき」に完成する。各ページで次の4問に答え、Yes のものは削る。

- [ ] **箱を1つ消しても**、読者は同じ結論に到達できるか
- [ ] **2つの箱を1つに統合できる**か（常に一緒に語られる2つは1つの概念）
- [ ] **矢印を消しても**関係が位置関係から読めるか
- [ ] **ラベルや注記を消しても**色・位置・見出しが同じことを伝えているか

削った結果、上限（`layouts.md` の索引）に収まらないなら、文字を小さくせずページを分ける。

## ページ単位

- [ ] **タイトルだけで主張が分かるか**（テーマ名になっていないか）
- [ ] **図だけ見ても論理が分かるか**（本文を読まないと意味が通らない図になっていないか）
- [ ] 図形の**位置に意味があるか**（左右・上下・中心と周辺が論理に対応しているか）
- [ ] 1ページに主張が複数混在していないか
- [ ] 最下部のメッセージが本当に **So What** になっているか（事実の要約で終わっていないか）
- [ ] 箱の中の情報の**粒度が揃っている**か
- [ ] 意味のない矢印・不要な分類・装飾がないか
- [ ] アクセント色（バーガンディ）が1ページ2箇所以内か
- [ ] ボックス内が3行以上になっていないか
- [ ] 2×2（#4）・比較表（#11）・シナリオ（#21）で、**象限名や列見出しが軸ラベルと同じ言葉**になっているか（軸は「柔軟性」なのに象限が「高コスト」では読者が数秒で不具合と判断する）

## ストーリー単位

- [ ] タイトルだけを上から読んで、資料全体の主張が通るか
- [ ] 前ページの結論が、次ページの問いになっているか
- [ ] 事実・仮説・解釈・結論が区別されているか
- [ ] 原因と結果を取り違えていないか（Why? を繰り返したか）
- [ ] 「だから何なのか」が言えないページがないか
- [ ] 数値・期間・体制が**ページをまたいで矛盾していない**か（例：本文の「Day45で判断」とガントのバーの位置）
- [ ] 最初に提示したストーリーライン表（ページ・タイトル・パターン）と完成物が一致しているか。変えたなら納品時にその旨を言う

## 組版

- [ ] `render.py` の検査が全ページ **OK**（`PAGE_OVERFLOW`／`FIG_OVERFLOW`／`SPILL`／`CLIP`／`BLEED`／`PN_MISMATCH` のいずれも出ていない）
- [ ] 最後の修正のあとに `render.py` を**もう一度**通したか（`--pages` で直したページだけでもよい）
- [ ] プロジェクト内に副産物（PNG・PDF）を残していないか
- [ ] PNGを実際に目視したか（検査OKでも図の意味崩れは検出できない）
- [ ] 罫線の太さ・箱の幅・間隔がページ間で揃っているか
- [ ] `.brand`（資料名）が全ページで同じか
- [ ] サンプル数値を使った場合、その旨を納品時に明記したか
- [ ] 既存のCSSルールを書き換えていないか（調整は `style=""` か新クラスの追記のみ）
- [ ] **`style=""` で `font-size` を雛形より小さくして収めた箇所がないか**（収まらないなら削るか分ける）
